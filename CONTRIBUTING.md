# Contributing

Taking part means following the [Code of Conduct](CODE_OF_CONDUCT.md). Report vulnerabilities privately ([SECURITY.md](SECURITY.md)), and never put real personal data in an issue, a pull request or a test: use made-up values of the same shape.

## Setup

```bash
nvm use            # Node 24 LTS (.nvmrc)
npm install
npm run build
npm test
npm run lint && npm run typecheck
```

Eval kit (Python 3.12, gitignored from npm publish): `cd packages/eval && python3.12 -m venv .venv && .venv/bin/pip install -e ".[presidio]"`. See `packages/eval/README.md`.

## Architecture rules

Non-negotiable — PRs that violate these will not be merged.

- **ML-first detection, regex as post-pass.** GLiNER is the primary detector; recognizers run after, never replace.
- **No cloud calls** for detection.
- **No `console.log`** in library code — use `debug` namespaced loggers (counts/ids only, never PII values).
- **No `any`.** TS strict mode + `exactOptionalPropertyTypes`.
- **No global mutable state.**
- **No circular imports.** `npm run circular-check` in CI + pre-commit.
- **Defaults centralised in `src/defaults.ts`.** `process.env` only via typed helpers in `src/config.ts`.
- **Apache-2.0 / MIT / BSD / ISC / CC0 deps only.** `npm run license-check` in CI.

## Tests

- TDD — tests before implementation.
- Public function = happy path + edge case + error case.
- Coverage thresholds (CI-enforced on the Ubuntu / Node 24 leg, over the core, its CLI and the gateway): 85% lines, statements and functions, 80% branches.
- Hardware-gated tests (CUDA/MPS) auto-skip when probe fails.

### Real-ONNX end-to-end (`npm run test:e2e`)

The default `npm test` mocks `OrtBackend` + `GlinerTokenizer` so CI stays ONNX-free. The opt-in E2E suite under `test/e2e/` loads the real GLiNER model and asserts representative fixtures produce representative spans — catches regressions in ScatterND clamping, decoder index math, chunk-boundary dedupe, recognizer/ML reconciliation, and the base64 layer.

```bash
# Point at a local model directory containing model.onnx + tokenizer.json
# + gliner_config.json + tokenizer_config.json.
NULLPII_MODEL_DIR=/path/to/model npm run test:e2e
```

`test/e2e/*.test.ts` are excluded from the default `vitest run`; the `test:e2e` script sets `NULLPII_E2E=1` so the same `vitest.config.ts` swaps include/exclude lists.

In CI the `e2e-onnx` job (`.github/workflows/ci.yml`) runs the same suite against the model the library pins (`DEFAULT_MODEL_REPO` and `DEFAULT_MODEL_REVISION` in `src/defaults.ts`): it builds the library, fails unless that revision is a 40-character commit SHA, fetches it with `nullpii prefetch` as a user's install would (cached between runs), and points `NULLPII_MODEL_DIR` at it. The job is opt-in: set the repository variable `NULLPII_E2E_ENABLED=true` once the pinned revision downloads anonymously from Hugging Face.

## Test data

nullpii is public, and so is every fixture. A test value must never be real.

**Fixtures** use reserved or obviously fake values:

| Kind | Use |
|---|---|
| E-mail, domain | `example.com`, `example.org`, `example.net`, or `*.example`, `*.test` (RFC 2606) |
| Phone | `555-01xx` (NANP fiction range), `+44 20 7946 0xxx` (Ofcom drama range) |
| Card | Network test numbers (`4111 1111 1111 1111`) |
| Secret | AWS's documented `AKIAIOSFODNN7EXAMPLE`, or a body that is visibly fake (`abcdef…`, `aBcDeF…`) |
| Person | Invented names; never a contributor's, customer's or public figure's |

IP addresses need care: `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24` and `2001:db8::/32` are documentation ranges that nullpii treats as never-PII. A test that expects an IP to be **detected** must use another range.

**Benchmark data** under `packages/eval/datasets/`: `nullpii-bench.jsonl` is generated by the project, never collected, and is the one exception to the fixture table: its secrets are random strings in the shape of real keys (`sk_live_…`, `ghp_…`, `AKIA…`), so that a detector is measured on realistic formats, and the secret scan allows that file by path; `presidio-synthetic.jsonl` is Microsoft's synthetic set, and the TAB ECHR files are published court judgments that name real people (see `packages/eval/datasets/README.md`). Never add collected text.

**Bug reports and leak reports** carry a repro with the values replaced, never the original text.

## What never goes in the repo

The pre-commit hooks and the `security` workflow block all of these:
- the contents of `packages/eval/private/` and `packages/eval/results/`;
- model weights;
- key material and `.env` files;
- files over 5 MB;
- absolute home paths (`/Users/<name>/`);
- private package registries in lockfiles;
- secrets.

Install gitleaks once (`brew install gitleaks`, or see https://github.com/gitleaks/gitleaks#installing) so they are also caught before you commit. CI blocks them either way. `npm run hygiene` checks the whole tree.

A fake value that gitleaks flags goes in `.gitleaks.toml` by exact value, with a reviewer confirming it is fake. Never allowlist a whole rule.

## Commits + PR

Conventional Commits (`feat`, `fix`, `docs`, `chore`, `refactor`, `perf`, `test`).

PR gate: `lint`, `typecheck`, `test`, `build`, `license-check`, `circular-check` and `sbom`, plus the `security` workflow (secret scan, repo hygiene, CodeQL, dependency review). All must pass. New public API needs JSDoc (`@param`, `@returns`, `@throws`, `@example`).

## Bug reports

Open an issue with: minimal repro, platform / Node version, nullpii version, redacted input. **Do not** attach raw PII.

## Security issues

See [SECURITY.md](SECURITY.md). Use the GitHub Security Advisory channel — do not open a public issue.

## Release checklist

One tag, `vX.Y.Z`, releases the library, the gateway and the Claude Code mod, which share a version. On the commit you will tag:

1. **Versions.** Set the new version in `package.json` and `package-lock.json` (`npm version X.Y.Z --no-git-tag-version` at the root), in `packages/gateway/package.json` and in `packages/claude-code-mod/.claude-plugin/plugin.json`; the release workflow refuses a tag that does not match all three. Bump SemVer per breaking / feature / fix. On every release, set the gateway's peer range on `nullpii` to `>=X.Y.Z-0 <X.(Y+1).0` with that release's own X.Y.Z (without a pre-release suffix, so `v0.6.0-rc.1` needs `>=0.6.0-0`): the gateway is built against the core of the same commit, so it never accepts a core from an older release line, and a pre-release gateway installs next to the pre-releases of its own version. The release workflow refuses any other range. Move the pinned versions users install: the marketplace tag in the mod's install commands (`lBroth/nullpii@vX.Y.Z`, in README.md and the mod's README), the `nullpii@X.Y` and `@lbroth/nullpii-gateway@X.Y` of the gateway command in the mod's README, and `nullpii@X.Y` in the mod's `nullpii-policy` skill (for a pre-release, the exact version, `nullpii@X.Y.Z-rc.N`: `X.Y` matches no pre-release). The release workflow checks the lockfile, every skill pin and, for a release, every marketplace pin too.
2. **Changelog.** Rename `## [Unreleased]` to `## [X.Y.Z] — YYYY-MM-DD` and open a new, empty `## [Unreleased]` above it. The GitHub release takes its notes from the `## [X.Y.Z]` section, and the release workflow refuses a tag without one (a pre-release tag `vX.Y.Z-rc.N` needs a `## [X.Y.Z-rc.N]` section).
3. **Model.** The library downloads the model revision it pins: a commit, never `main`, in `DEFAULT_MODEL_REVISION`, and each file's SHA-256 in `DEFAULT_MODEL_SHA256` (both in `src/defaults.ts`; `DEFAULT_MODEL` in `src/model-manager.ts` carries the map, and `test/default-model-pin.test.ts` checks that every file the model can fetch has a 64-hex hash). The release workflow refuses a tag until the revision is a commit and the map is wired in. If the model changed, publish it to `lBroth/nullpii` on Hugging Face, update both pins, and run the real-ONNX suite against it (`npm run test:e2e`, see [Tests](#tests)).
4. **Clean build.** `npm run clean && npm run build` (the `prebuild` hook runs `clean` automatically). Confirms no orphan `dist/*.js` from deleted `src/` files.
5. **Pack inspection.** `npm pack --dry-run` at the root. Verify every shipped file is intentional:
   - Only `package.json` and the paths in its `files` are listed: `dist/`, `src/`, `bin/`, `assets/logo.png`, `README.md`, `LICENSE` and `NOTICE`.
   - `dist/backend/` contains **only** `backend.{js,d.ts,*.map}`.
   - No orphan compiled outputs in `dist/` from modules that no longer exist in `src/`.
   - The tarball stays small: model weights ship through Hugging Face, not npm.

   Then, in `packages/gateway`, `npm publish --dry-run`: it runs the same `prepublishOnly` as the release, which compiles the gateway against the root `dist/`, and lists only `package.json`, `dist/`, `src/`, `bin/`, `README.md`, `LICENSE` and `NOTICE`. Delete the `dist/` and `node_modules/` it leaves in `packages/gateway` afterwards.
6. **Full quality bar.** `npm run lint && npm run typecheck && npm run test:coverage && npm run license-check && npm run circular-check && npm run hygiene && npm run docs:build`, and CI green on the release commit (CI also runs the mod's tests and the eval kit's).
7. **Bench refresh.** If the runtime pipeline or the model changed, measure it with the method in `packages/eval/METHOD.md`, and fill the README and METHOD tables from the scored JSON; never type a number by hand.
8. **Tag.** Push `vX.Y.Z` from a commit on main, soon after the merge: `docs.yml` publishes the site on every push to main that changes one of its pages (the READMEs among them), so its install commands name the new version before the packages exist until the tag is out. `.github/workflows/release.yml` checks the versions and runs the gate (the coverage thresholds and the mod's checks included); publishes `nullpii`, then `@lbroth/nullpii-gateway`, with provenance through npm trusted publishing (each publish job waits for the `npm` environment's reviewer); then creates the GitHub release with the changelog section and the SBOM (`bom.json`), and, once both packages are on npm, runs `.github/workflows/gateway-docker.yml`, which builds the image and pushes `ghcr.io/lbroth/nullpii-gateway` as `X.Y.Z`, `X.Y` and `latest`. It refuses to start unless `DEFAULT_MODEL_REVISION` is a commit and `DEFAULT_MODEL_SHA256` pins every file. A pre-release tag (`vX.Y.Z-rc.N`) publishes under npm's `next` dist-tag, as a GitHub pre-release, and moves no `latest` tag.
9. **After.** Check that both npm pages show provenance, that the GitHub release carries the right notes, and that the image tags exist. GHCR creates a package private on its first push: once, make `nullpii-gateway` public (its package settings on GitHub, Change visibility).
