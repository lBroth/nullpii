# Retrain plan — full-OSS unified model (v0.2 track)

Goal: make the published model weights cleanly redistributable under a
permissive licence, collapse the 5 per-domain LoRA adapters + cosine router
into a **single model**, and shrink the runtime download from ~6 GB to a few
hundred MB. Decided 2026-05-11; supersedes the standalone "drop Nemotron-PII
from the enterprise adapter" idea (Nemotron-PII is CC-BY-4.0 — not a licence
problem).

> Training scripts live in `packages/eval/private/` (gitignored, GPU). This
> file is the runbook; the actual training runs off-repo. Everything tracked
> that this plan touches is listed under "Phase 4 — ship".

## Why

| Dataset | nullpii use today | Upstream licence (checked 2026-05-11) | Verdict |
|---|---|---|---|
| `urchade/gliner_multi_pii-v1` | base model | Apache-2.0 | keep |
| `sentence-transformers/distiluse-base-multilingual-cased-v2` | router input encoder | Apache-2.0 | **drop** (router goes away) |
| `nvidia/Nemotron-PII` | training (enterprise adapter) + eval | **CC-BY-4.0** — commercial OK, attribute NVIDIA | keep (training + eval) |
| Text Anonymization Benchmark (TAB / ECHR) train | training (legal adapter) | MIT (TAB release) + public court docs | keep |
| `ai4privacy/pii-masking-300k` | training + eval (`-heldout`) | `license: "other"` (custom `license.md`): academic-with-citation OK, **commercial gated** (`licensing@ai4privacy.com`) | **drop from training**; eval-only only if we don't redistribute the JSONL |
| `Isotonic/pii-masking-200k` | training + eval (`-heldout`) | **cc-by-nc-4.0** (NonCommercial) | **drop from training**; same eval caveat |
| project-authored Faker / templated corpora | training | Apache-2.0 (`packages/eval/datasets/`) | keep |

Consequence today: the adapters are trained on ai4privacy-300k + Isotonic-200k,
so the weights can't be Apache-2.0 for commercial use. This plan removes those
from *training*.

## Target architecture

Before: `urchade/gliner_multi_pii-v1` backbone → 5 LoRA adapters, each merged
into a full ONNX copy of the backbone (≈5 × ~1.1 GB) + distiluse encoder +
`router-embeddings` prototypes → at inference, distiluse embeds the input,
cosine routing picks one merged model.

After: one LoRA (or full fine-tune) on the **union** of the per-domain training
data → one merged ONNX → quantize int4. No router, no distiluse, no per-domain
prototypes, no 5× backbone duplication.

- fp32 unified ≈ ~1.1 GB · int4 unified ≈ ~300–400 MB (CLI already has
  `--variant int4` plumbing).
- Runtime code simplifies: delete the router / distiluse / prototype load path,
  shrink the `model-manager` file manifest to one ONNX + tokenizer.

Fallback if the unified model regresses too far (see Phase 3 gate): keep the
router, but swap each adapter's *training* data to permissive-only. That still
clears the licence blocker; it does **not** shrink the download unless we also
ship `base backbone + 5 × ~17 MB LoRA delta` and merge at install time (onnxruntime
can't apply LoRA at runtime, so this needs a Python merge step in the install
flow — messier; only do it if forced down the fallback path).

## Permissive-only training pool

Anchor the new training corpus on:

- **NVIDIA Nemotron-PII** train split — CC-BY-4.0, ~large synthetic, 55 fine
  classes → remap to nullpii's 8-class schema (`nullpii_eval.public_datasets`
  already has the NER→8-class map; extend for Nemotron's labels).
- **TAB / ECHR** train split — MIT; legal-domain person/address/date.
- **presidio-synthetic** — MIT, generated by Presidio's eval lib; can be
  regenerated to arbitrary size with the Presidio generator (no licence limit).
- **project-authored Faker / templated** — `packages/eval/datasets/{en,de,fr,it,es}-baseline.jsonl`
  + `dev-paste-synth-train.jsonl` + the `*-templates.txt` generators — Apache-2.0.
- **conll2003 / wikiann** — open NER sanity (PER/LOC only; loose 8-class map).
- **cc-negative-25k** — Apache-2.0 no-PII regularizer (keep).

Explicitly NOT in training: `ai4privacy/pii-masking-300k`, `ai4privacy/pii-masking-400k`,
`Isotonic/pii-masking-200k`, `bigcode/bigcode-pii-dataset` (gated). Wire this in
`packages/eval/src/nullpii_eval/public_datasets.py` (the `DatasetName` set + a
`PERMISSIVE_TRAINING` allowlist) so the training config can only pull from it.

## Phase 0 — smoke (minutes; proves the pipeline without ai4privacy/Isotonic)

1. Build a tiny multi-domain training set: ~300–500 rows sampled across the
   permissive pool above (e.g. 100 Nemotron-PII + 100 TAB + 100 presidio-synthetic
   + 100 Faker), 8-class labels.
2. Train one LoRA (rank 8, 1 epoch) on the `urchade/gliner_multi_pii-v1` backbone
   — reuse the per-domain training script in `private/`, just point it at the
   unified set and a single adapter dir.
3. Merge → export ONE ONNX via a `scripts/release/export_unified_onnx.py`
   (forked from `export_merged_lora_onnx.py`, single adapter instead of 5; no
   `export_router_artifacts.py` call).
4. `python scripts/bench_full.py --tools nullpii --datasets <OOD-6> --cap 200 --backend cpu`
   — should run end-to-end and produce a (bad, tiny) F1. Success = pipeline
   green, no router/distiluse needed.

## Phase 1 — full retrain

1. Full permissive pool, balanced per domain; hold out the OOD eval rows
   (presidio-synthetic, and — if still using them eval-only — ai4privacy-300k /
   isotonic `*-heldout` slices, kept download-only, not redistributed).
2. One LoRA, rank ~16–32, proper epochs / early-stop on a permissive dev split.
   Try also a full fine-tune (no LoRA) as a comparison point — there's only one
   model now, so the LoRA-vs-full tradeoff is just size/time, not 5×.
3. Sweep: does adding back the 5 "domain" signals as a prompt/instruction
   prefix (instead of routing) recover any of the per-domain gain?

## Phase 2 — export & quantize

1. `export_unified_onnx.py` → `model.onnx` (fp32) + tokenizer + `gliner_config.json`.
2. int4 quantize (onnxruntime quantization, matching whatever the existing
   `--variant int4` path expects) → `model.int4.onnx`.
3. Publish to `lBroth/nullpii` (replace the 5-shard + distiluse layout). Bump
   the model repo revision pin in `src/defaults.ts`.

## Phase 3 — re-bench & decision gate

`python scripts/bench_full.py --tools nullpii,presidio,nemotron-pii-raw,piiranha,deberta,gliner-onnx-pii-fp32,gliner-pii-large-v1 --datasets <canonical surface> --cap 5000 --backend cpu`

Gate (vs the current routed model's headline = **held-out OOD multilingual macro F1 0.7662**):

- **Ship the unified model** if OOD-6 macro F1 ≥ ~0.74 (within ~2–3 pts) — the
  size + simplicity win is worth a small accuracy cost.
- **Fall back to routed-but-permissive** if it lands < ~0.70 — keep the router,
  permissive training data per adapter, accept the larger download (or take on
  the install-time LoRA-merge to shrink it).
- Record the new full matrix at `packages/eval/published-bench/matrix.{csv,json}`.

## Phase 4 — ship (the tracked-file changes)

When the unified model is chosen:

- `src/` — delete the router / distiluse / prototype load path; `model-manager`
  file manifest → one ONNX + tokenizer (+ int4 variant); drop `router-embeddings`
  handling; simplify `defaults.ts`.
- `packages/eval/scripts/release/` — add `export_unified_onnx.py`; retire
  `export_router_artifacts.py` and the 5-shard path in `export_merged_lora_onnx.py`
  (or keep behind a flag for the fallback).
- `packages/eval/src/nullpii_eval/public_datasets.py` — add the `PERMISSIVE_TRAINING`
  allowlist; extend the label map for Nemotron-PII's 55 classes.
- `packages/eval/weights/adapters/` — replace the 5 per-domain `adapter_config.json`
  dirs with one unified adapter config; drop `weights/router/`.
- Docs: re-run the bench and rewrite the bench tables + headline metric in
  `README.md`, `CHANGELOG.md`, `COMPETITIVE_ANALYSIS.md`; update `NOTICE`
  (remove the BLOCKER note, list the final permissive training set, keep the
  NVIDIA Nemotron-PII CC-BY-4.0 attribution); update `PLAN.md` to mark this track
  done; update `packages/eval/datasets/README.md`.
- `package.json` / model size claims everywhere ("~6 GB" → new figure; "First-call
  download" blurb in README).

## Open questions

- Eval JSONL redistribution: keep `ai4privacy-300k-heldout` / `isotonic-*-heldout`
  as download-only eval sets, or replace them with permissive OOD sets so the
  whole eval kit is redistributable? (Affects the bench surface + headline.)
- Multilingual coverage: ai4privacy/Isotonic were a big chunk of the de/fr/it/es
  training signal. Does Nemotron-PII + Faker templates + wikiann cover en/de/fr/it
  well enough, or do we need another permissive multilingual PII set?
- int4 accuracy hit: quantization usually costs ~1–2 F1 pts on top of the
  unification cost — re-check the Phase 3 gate against the int4 variant, not just fp32.
