# AB-1, an agentic masking benchmark (pre-registered 2026-10-23)

Written before any set is built and before any tool runs on it. The model under report is already chosen (rule change 16: P0, the H3b weights) and no model is trained after this point for 0.5, so nothing here can steer a training or selection decision. AB-1 is reported, never used to choose (rule 16.5).

## What it measures

A coding agent (Claude Code, Copilot CLI, OpenHands…) sends the model two kinds of text: what the user types, and what tools return (files, shell output, logs, diffs, tickets). A masker in front of the model must hide what is dangerous to hand over and leave the rest readable, or the agent cannot work. AB-1 scores both sides, per category, with no single combined score:

- **leak**: dangerous values that reach the model;
- **keep**: values the agent needs that the masker hides.

Scoring is **label-agnostic**: an item counts as masked when a tool masks its characters, whatever label the tool gives them. A tool that masks a key as `PASSWORD` or `ID` has still protected it. No label maps, so no label-map choices to argue about.

### A. Agent traffic

**Document kinds** (shares of A, each kind split 1/6 dev, 5/6 test):

| Kind | Share | Language |
|---|---|---|
| User prompts to a coding agent | 20% | en, it, de, fr, es (equal) |
| File reads: source, `.env`, YAML/JSON/TOML config, Dockerfile, CI files | 20% | en |
| Shell output: `git log`, `git diff`, `curl -v`, `env`, `docker`/`kubectl` output, test runs | 20% | en |
| Logs and stack traces (app logs, tracebacks with home paths) | 15% | en |
| Tool-call arguments as JSON (`Edit`, `Write`, `Bash` input) | 10% | en |
| Issue and ticket text pasted into the agent | 15% | en, it, de, fr, es (equal) |

**Carriers.** Half of each kind starts from real agent material, half from the builder's own templates:
- [nebius/SWE-rebench-openhands-trajectories](https://huggingface.co/datasets/nebius/SWE-rebench-openhands-trajectories) (CC BY 4.0, revision `35455389ab51bf5e2306bfd436ef72d0f98bf882`): tool calls, bash output and diffs from OpenHands runs on public repositories;
- [OpenHands/openhands-feedback](https://huggingface.co/datasets/OpenHands/openhands-feedback) (MIT, revision `facf45600d625510b98222ec584a8c9ac59272a2`): real user sessions;
- excerpts are cut at line boundaries, 300–6,000 characters; the carrier id and offsets are recorded.

**Injection.** Values go where they really occur: `.env` lines, `Authorization: Bearer` headers, DB connection strings, `git log` author lines, `/Users/<name>/` and `/home/<name>/` paths in tracebacks, `From:`/`To:` lines, log fields (`user=`, `email=`, `customer_id=`), config blocks.
- 20% of documents get no injected value (clean documents).
- 5% of injected values appear a second time in the same document base64- or URL-encoded (`kubectl get secret -o yaml`, query strings); the encoded copy is its own item linked to the original.
- Values are format-valid: Luhn-valid card numbers, mod-97 IBANs, national ids with valid check characters, provider keys with the provider's published prefix, length and charset (checksums where the provider publishes one). Key formats are drawn with a seed from the rule list of [gitleaks](https://github.com/gitleaks/gitleaks) (MIT), uniformly across rules, so formats are not chosen by anyone who knows nullpii.
- Names and addresses come from public-domain or permissively licensed lists the builder picks and records, for the five languages. Not from Faker (the training data used it).
- Values are generated by the builder's own code with recorded seeds; every value is fictional. No real credential, ever.

### B. Secret slices

- **B1.** Each sampled CredData line with 5 lines of context above and below is one document. The line's labelled value span is the item: `GroundTruth = T` is MUST_MASK (secret), `F` is MUST_KEEP (the upstream labels say placeholders, env references, hashes, dummies). Sample seed 0, stratified by CredData category; the download script is pinned to a commit.
- **B2.** Each candidate with the issue text around it (1,000 characters on each side, cut at whitespace) is one document; the candidate value is the item, true → MUST_MASK, false → MUST_KEEP. If the release does not hold the issue text, B2 is dropped and the drop is logged; nothing is substituted.
- B1 and B2 have no AMBIGUOUS class and no other scored items; masking outside the item is counted only as masked characters per 1k.

## Classes (component A)

Every annotated item has one class. Lists are closed: a kind not listed is not annotated.

**MUST_MASK** (category in brackets, as the default policy names it):
- secrets [secret]: API keys and tokens, passwords, private keys, JWTs, session cookies, the password inside a connection string, a token inside a URL (the token only);
- people [person]: private persons' names, OS usernames in home paths, display names in email headers and `git log` author lines;
- contacts [email, phone, address]: personal email addresses, phone numbers, postal addresses;
- ids and accounts [account and the id categories]: IBANs, card numbers, national and tax ids, passport and driver licence numbers, customer and user account numbers;
- network [ip, mac]: public IP addresses that are not documentation ranges, MAC addresses;
- personal URLs [url]: profile pages and personal sites that identify a private person.

**MUST_KEEP**:
- code identifiers, including name-like ones (`getMarioConfig`, `class Rossi`);
- public URLs: documentation, package registries, code hosts, public APIs;
- commit SHAs, UUIDs, checksums, integrity hashes, version strings;
- dates and timestamps;
- company, product and project names; job titles; honorifics;
- placeholders and references: `YOUR_API_KEY`, `<token>`, `xxx…`, `${VAR}`, `$API_KEY`, `${{ secrets.X }}`, `example.com`/`example.org` addresses, RFC 5737 and RFC 3849 addresses, `127.0.0.1`, `::1`, `0.0.0.0`, `localhost`;
- ticket, issue and PR numbers, line numbers, ports, PIDs, HTTP status codes;
- file paths, except the username part of a home path (annotated MUST_MASK).

**AMBIGUOUS** (annotated, never scored):
- real PII-like strings already in carriers (found by the builder's own regex pass for emails, phones, IPs and key-like strings, then reviewed), so a real value nobody injected cannot count against any tool;
- names in licence headers and copyright lines, public figures, maintainers' GitHub handles;
- role addresses (`support@`, `noreply@`, `security@` on a real domain);
- internal hostnames and URLs, RFC 1918 and link-local IPs;
- order and invoice numbers; birth dates; dummy credentials in test fixtures (`password123`, `changeme`).

## Metrics

All metrics are computed on character spans each tool masks (its output offsets), on the test split, for every tool the same way.

**Primary, reported side by side per category and overall:**
- **Leak rate**: share of MUST_MASK items with at least one character not masked. Partial masking is a leak.
- **Keep rate**: share of MUST_KEEP items with no character masked.

**Secondary:**
- documents with at least one leak;
- clean documents with any masked character;
- masked characters outside every annotated item, per 1,000 characters;
- encoded leak rate (the encoded copies alone);
- secrets: leak rate on key formats that nullpii's recognizer pack covers and on those it does not (the split is computed after freezing, from the pack's source, and only reported);
- structure: with every masked span replaced by `{{MASK_n}}`, share of JSON documents that still parse, and of diff documents that still pass `git apply --check` against their carrier's pre-image where it is available;
- nullpii only: `restore(mask(x)) == x` on every document.

**Uncertainty:** paired bootstrap over documents, 1,000 resamples, seed 0, 95% intervals, for each metric and each difference between nullpii and another tool. A difference is called a win or a loss only when its interval excludes 0. Latency is not measured here.

## Tools

Every tool in the R4 report, through the same adapters and full upstream pipelines, plus nullpii P0 in the default it ships (`DEFAULT_DISABLED_CATEGORIES`). Two rows each:
- **default**: the tool as it ships;
- **agent policy**: where the tool can turn categories off, the categories this policy leaves readable (dates, organisations, occupations, titles, demographic and sensitive attributes) turned off. Tools that cannot have only the default row.

Thresholds are not tuned on AB-1. Adapters are not changed after the first run on the test split; a needed fix applies to every tool, is logged, and the whole run is redone.

## Independence and freezing

1. **Builder.** One fresh agent builds A from this file alone, in a directory outside the nullpii repositories. It does not read any nullpii repository, training corpus, generator, tuning set, report set or model, and does not run nullpii. It writes its generator code, the value lists and their sources, seeds, carrier ids and revisions, the gold, and a README.
2. **Audit.** A second fresh agent, with the same restrictions, labels a random 10% of A's documents (seed 0) from this file and the raw text, without the gold. Agreement is reported per class (Cohen's kappa) and the share of gold items it finds wrong or missing. If more than 5% are wrong, the builder fixes the cause and a new 10% sample is audited.
3. **Freeze.** SHA-256 of every file of A (code, lists, gold, README) and of B1/B2's sampled id lists, and the canary string `AB1-CANARY-6f3a1c9e-nullpii-agentbench-2026-10-23` placed in A's README and gold, go to LOG.md before any tool runs. The scorer (`agent_metrics.py`) is written and hashed before the first run too.
4. **Leak checks** (after freezing, before running): no carrier excerpt shares a 13-gram MinHash near-duplicate (Jaccard ≥ 0.8) with any nullpii training source, and no injected value occurs verbatim in any training corpus. Hits are dropped from the test split, counted and logged; nothing is added back.
5. **One run.** The test split is run once for this release, every tool, and every number is published, including the ones nullpii loses.

## Reporting

- The benchmark page gets an AB-1 section beside the existing ones, with both rows per tool, both primary metrics per category, and the intervals.
- The page also states what the other sets measure: PIILO is student essays and rizzo-pii is built for documents; they measure document anonymisation, a different job from masking an agent's traffic. Their numbers stay on the page unchanged.
- B1 and B2 are reported as aggregates only. CredSweeper's B1 row, if it is run, is marked in-distribution (its model is trained on CredData).
